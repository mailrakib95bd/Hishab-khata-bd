# হিসাব-খাতা — ইনস্টলযোগ্য ওয়েব-অ্যাপ (PWA)

এই ফোল্ডারে আপনার `hisab-khata.jsx` কে একটি সম্পূর্ণ, ফোনে ইনস্টল করা যায় এমন
ওয়েব-অ্যাপ (Progressive Web App) হিসেবে প্যাকেজ করা হয়েছে।

## ফাইলগুলো কী করে
- `index.html` — মূল পেজ। React ও Babel ব্রাউজারে লোড করে `app.js` (আপনার
  অ্যাপের কোড) সরাসরি চালায় — আলাদা করে বিল্ড/কম্পাইল করার দরকার নেই।
- `app.js` — আপনার `hisab-khata.jsx`-এর কোড (শুধু `import`/`export` লাইন
  সরানো হয়েছে যাতে ব্রাউজারে সরাসরি চলে; ভেতরের সব ফিচার অপরিবর্তিত)।
- `manifest.json` — ফোনের হোম স্ক্রিনে "ইনস্টল" করার তথ্য (নাম, আইকন, রং)।
- `sw.js` — সার্ভিস ওয়ার্কার, যা একবার খোলার পর অফলাইনেও অ্যাপ চালু রাখতে সাহায্য করে।
- `icon-192.png`, `icon-512.png` — অ্যাপ আইকন।

## কীভাবে চালাবেন / ইনস্টল করবেন
সার্ভিস ওয়ার্কার ও "ইনস্টল" ফিচার কাজ করতে হলে এটি HTTPS-এ হোস্ট করা লাগবে
(শুধু ফাইল ডাবল-ক্লিক করে খুললে হিসাব রাখা কাজ করবে, কিন্তু অফলাইন/ইনস্টল
ফিচার কাজ নাও করতে পারে)। সবচেয়ে সহজ ফ্রি উপায়:

1. **GitHub Pages**: এই ফোল্ডারের ফাইলগুলো একটি GitHub রিপোজিটরিতে আপলোড
   করুন → Settings → Pages থেকে চালু করুন। কিছুক্ষণ পর একটি লিংক পাবেন।
2. **Netlify Drop** (netlify.com/drop): এই ফোল্ডারটি সরাসরি টেনে
   (drag-and-drop) দিলেই একটি লিংক তৈরি হয়ে যাবে — কোনো অ্যাকাউন্ট ছাড়াই।
3. **Vercel / Cloudflare Pages**: একইভাবে ফোল্ডার আপলোড করে ফ্রি হোস্ট করা যায়।

লিংক পাওয়ার পর ফোনের ব্রাউজারে (Chrome/Safari) খুলুন → মেনু থেকে
**"Add to Home Screen" / "হোম স্ক্রিনে যোগ করুন"** চাপুন — তাহলে এটি একটি
সাধারণ অ্যাপ আইকনের মতো ইনস্টল হয়ে যাবে এবং পূর্ণ স্ক্রিনে চলবে।

## ডেটা কোথায় থাকে
অ্যাপটি ফোনের ব্রাউজারের `localStorage`-এ ডেটা সংরক্ষণ করে — অর্থাৎ ডেটা
থাকে সম্পূর্ণ আপনার ডিভাইসেই, কোনো সার্ভারে যায় না। ব্রাউজারের ডেটা/ক্যাশ
মুছে ফেললে হিসাবও মুছে যাবে, তাই মাঝে মাঝে সেটিংস থেকে CSV এক্সপোর্ট করে
ব্যাকআপ রাখা ভালো।

## 📱 ফ্রী APK বানানো (GitHub Actions — নিজের পিসিতে Android Studio লাগে না)

1. এই ফোল্ডারের সব ফাইল (লুকানো `.github/` ও `.gitignore` সহ) GitHub রিপোজিটরিতে আপলোড করুন।
2. রিপোজিটরির **Actions** ট্যাব → **Build Android APK** → **Run workflow**।
3. ৫–১০ মিনিট পর বিল্ড শেষ হলে সেই রানের পাতার নিচে **Artifacts → HishabKhata-App** থেকে `app-debug.apk` নামান।
4. ফোনে APK খুলে ইনস্টল করুন (Settings-এ "Install unknown apps" চালু করতে হতে পারে)।

কী হয় ভেতরে: `npm run build` শুধু ওয়েব-ফাইলগুলো `www/`-তে কপি করে এবং React লোকাল `vendor/`-এ বসায় (APK-তে CDN লাগে না); তারপর `cap add android` → `cap sync` → `gradlew assembleDebug`। `android/` ফোল্ডার প্রতিবার নতুন তৈরি হয়, তাই কমিট করতে হয় না।

**জেনে রাখুন**
- এটি **debug APK** — নিজের ফোনে/বন্ধুদের দিতে ঠিক আছে। Play Store-এর জন্য signed release বিল্ড আলাদা ধাপ।
- Firebase (লগইন/ক্লাউড ব্যাকআপ) স্ক্রিপ্ট `gstatic.com` থেকে লোড হয়, তাই ওই ফিচারগুলোর জন্য ইন্টারনেট লাগবে; স্থানীয় হিসাব অফলাইনেও চলবে। Google Sign-In WebView-তে আলাদা কনফিগ ছাড়া কাজ নাও করতে পারে — ফোনে টেস্ট করে দেখতে হবে।
- খসড়া খাতার প্রিন্ট/পিডিএফ APK-তে সিস্টেম শেয়ার-শিট খোলে (Files-এ সেভ, WhatsApp, প্রিন্ট)।
- লোকালি বানাতে চাইলে: `npm install && npm run build && npx cap add android && npx cap sync android && cd android && ./gradlew assembleDebug` (Node 20+, JDK 17+)।

## Phase 2 — ক্লাউড অ্যাকাউন্ট / Backup চালু করা

অ্যাপে এখন Settings → "অ্যাকাউন্ট" থেকে Google বা ইমেইল দিয়ে সাইন-ইন করে
ক্লাউডে ব্যাকআপ/সিঙ্ক করা যায়। এটা কাজ করানোর জন্য Firebase কনসোলে দুটো
ছোট কাজ করতে হবে (একবারই):

1. **Firestore Security Rules বসানো** — এই ফোল্ডারের `firestore.rules`
   ফাইলের পুরো লেখাটা কপি করুন → Firebase Console → আপনার প্রজেক্ট →
   Build → Firestore Database → **Rules** ট্যাব → পুরনো লেখা মুছে এটা
   পেস্ট করে **Publish** চাপুন। এটা ছাড়া কেউ কারো ডেটা লিখতে/পড়তে
   পারবে না (এমনকি নিজেরটাও না)।

2. **Authorized domain যোগ করা (Google Sign-In-এর জন্য জরুরি)** —
   Firebase Console → Authentication → Settings → **Authorized domains**
   ট্যাবে গিয়ে আপনার হোস্ট করা লিংকের ডোমেইনটা (যেমন
   `yourapp.netlify.app`) যোগ করুন। এটা ছাড়া Google দিয়ে সাইন-ইন করলে
   `auth/unauthorized-domain` এরর দেখাবে।

**গুরুত্বপূর্ণ পার্থক্য — কোন ভার্সনে কী কাজ করবে:**
- **হোস্ট করা ভার্সন** (এই zip, Netlify/GitHub Pages-এ আপলোড করার পর):
  Google Sign-In ও ইমেইল লগইন — দুটোই ঠিকমতো কাজ করবে।
- **`hisab-khata-standalone.html`** (সরাসরি ফোনে খোলা, হোস্ট করা ছাড়া):
  ইমেইল/পাসওয়ার্ড লগইন হয়তো কাজ করবে, কিন্তু **Google Sign-In কাজ
  নাও করতে পারে** — Google-এর OAuth পদ্ধতি একটা আসল ওয়েব ঠিকানা
  (https://...) দাবি করে, `file://`/`content://` থেকে না। ক্লাউড
  ফিচার পুরোপুরি ব্যবহার করতে চাইলে হোস্ট করা ভার্সনটাই ব্যবহার করুন।

**ডেটা কোথায় থাকে:** প্রতিটি ব্যবহারকারীর সব হিসাব একটামাত্র নথিতে —
`users/{আপনার UID}` — জমা থাকে Firestore-এ। ডিভাইসের PIN কখনো ক্লাউডে
পাঠানো হয় না, সেটা শুধু সেই ডিভাইসেই থাকে।

## 🛒 ফ্যামিলি বাজার (Family Bazar)

পরিবারের সবাই নিজের বাজার লেখে; কে কত খরচ করল, কোন পণ্যের দাম বাড়ল/কমল, এলাকাভেদে দামের তুলনা — সব এক জায়গায়। ব্যক্তিগত হিসাব-খাতার ডেটা এতে বদলায় না।

**কোথায় আছে:** ☰ মেনু → *ফ্যামিলি বাজার* (ফুল-স্ক্রিন) এবং নিচের *ফ্যামিলি* ট্যাবের প্রথম অংশ। ট্যাবের দ্বিতীয় অংশ *ব্যক্তিগত তালিকা* — আগের লোকাল পরিবার/বাজার তালিকা, অপরিবর্তিত।

| ফাইল | কাজ |
| --- | --- |
| `family-bazar-core.js` | শুধু লজিক (টাকার হিসাব, অনুমতি, দামের বিশ্লেষণ, write-plan) — Node-এ টেস্টযোগ্য |
| `family-bazar.js` | সব স্ক্রিন (Home, Bazar, Reports, Family, More + sheets) |
| `firebase-init.js` | Firestore ডেটা-লেয়ার (`window.FB`) |
| `firestore.rules` | **আসল সিকিউরিটি** — ফ্রন্টএন্ড লুকানোর ওপর ভরসা নেই |
| `tests/` | `npm test` — core + expense-sync + family-bazar-shopping + task-amount + tax-reminder + special-day-hijri + special-day-bulk-import + hijri-ummalqura + khasra-khata + khasra-ui + UI smoke — ১৯০+টি |

**Deploy করার ধাপ**
1. Firebase Console → Firestore → Rules-এ `firestore.rules` পেস্ট করে Publish।
2. Authentication → Sign-in method-এ Google চালু; Settings → Authorized domains-এ আপনার ডোমেইন যোগ।
3. কোনো composite index লাগে না (সব কোয়েরি equality-ভিত্তিক)।
4. `index.html`-এ `?v=` এবং `sw.js`-এর `CACHE_NAME` বাড়ানো আছে — পুরনো cache নিজে থেকে বদলাবে।

**Invitation:** কোনো ইমেইল যায় না। প্রাপক ওই Gmail দিয়ে Google Sign In করলে ফ্যামিলি বাজারে Invitation দেখতে পান (☰ মেনুতে ব্যাজও আসে) এবং Accept করেন। ইমেইল/পাসওয়ার্ড অ্যাকাউন্ট থেকে Accept করা যায় না, কারণ সেই ইমেইল যাচাই করা থাকে না।

### ফ্যামিলি বাজার থেকে ব্যক্তিগত ব্যয়ে অটো-সিঙ্ক

কেউ ফ্যামিলি বাজারে একটি কেনাকাটা সংরক্ষণ করলে সেটা তার **নিজের** ব্যক্তিগত হিসাব-খাতার লেনদেনেও একটি নির্দিষ্ট ক্যাটাগরিতে ("🛒 ফ্যামিলি বাজার") যোগ হয়ে যায় — যাতে ব্যক্তিগত রিপোর্ট/ব্যালেন্সেও এটা ধরা পড়ে। এই ক্যাটাগরিটি প্রথমবার লাগলে নিজে থেকেই তৈরি হয়ে যায়, পরে কেউ নাম বদলালে সেটাই ব্যবহার হয়। কেনাকাটা এডিট/মুছে ফেললে সংশ্লিষ্ট লেনদেনও আপডেট/মুছে যায় (`purchaseId` দিয়ে লিংক করা)। পরিবারের অন্য সদস্যরা এই কেনাকাটা আগে থেকেই ফ্যামিলি ট্যাব থেকে দেখতে পান (অনুমতি অনুযায়ী) — তাই এই সিঙ্ক শুধু কেনার ব্যক্তির নিজের হিসাবে যোগ করে, অন্য কারও একাউন্টে কিছু লেখে না।

### বাজারের তালিকা (Shopping Lists) + রিমাইন্ডার

- যেকোনো সদস্য (viewer বাদে) নিজের জন্য বা পরিবারের অন্য যেকোনো সক্রিয় সদস্যের জন্য একটি "কী কিনতে হবে" তালিকা বানাতে পারেন (আরও ট্যাব → বাজারের তালিকা, অথবা হেডারের 📝 আইকন)।
- তালিকায় ঐচ্ছিক রিমাইন্ডার দেওয়া যায় — নির্দিষ্ট তারিখে একবার, অথবা প্রতিদিন — যতক্ষণ তালিকায় কেনা বাকি থাকে।
- রিমাইন্ডার শুধু তখনই কাজ করে যখন যাকে অ্যাসাইন করা হয়েছে তার ডিভাইসে অ্যাপ খোলা থাকে (২০ সেকেন্ড পরপর চেক হয়, ঠিক app-এর নিজের Task রিমাইন্ডারের মতোই) — এটা একটা client-only PWA, তাই অ্যাপ পুরো বন্ধ থাকা অবস্থায় নোটিফিকেশন পাঠানো সম্ভব নয় (তার জন্য push server লাগবে)।
- ফ্যামিলি/ফ্যামিলি বাজারের হেডারে 📝 আইকনে তালিকায় কতগুলো পণ্য বাকি আছে তার সংখ্যা ছোট্ট ব্যাজ আকারে দেখা যায়।
- পণ্যের নাম ও ক্যাটাগরি দুটোই এখন বাধ্যতামূলক (তালিকা তৈরির সময়, আর "+ নতুন পণ্য যোগ করুন" দিয়ে যোগ করার সময়ও) — ক্যাটাগরি ছাড়া আর সংরক্ষণ করা যায় না।
- তালিকার ভেতরেই প্রতিটি বাকি পণ্যের পাশে ছোট করে **পরিমাণ + একক + একক দাম** লেখা যায়; মোট স্বয়ংক্রিয়ভাবে হিসাব হয়। **পরিমাণ ও একক দাম দুটো না দেওয়া পর্যন্ত সেই পণ্যের টিক-বক্স বন্ধ (disabled) থাকে** — তাই দাম ছাড়া ভুলে "সম্পন্ন" চিহ্নিত হয়ে যাওয়ার সুযোগ নেই। একাধিক পণ্য টিক দিয়ে একসাথে "সংরক্ষণ করুন" চাপলে সব কটা **একটিমাত্র কেনাকাটা হিসেবে** (তারিখ/বাজার/এলাকা/নোট/দামের-ইতিহাস-টগল সহ, আগের "নতুন বাজার যোগ করুন" ফর্মের ঠিক একই পাইপলাইন দিয়ে) সংরক্ষিত হয় ও তালিকা থেকে সরে যায়; বাকি পণ্যগুলো তালিকাতেই থেকে যায় — আলাদা পেজে যেতে হয় না, পুরোটাই এক স্ক্রিনে।
- তালিকা পাঠানো ব্যক্তি (বা যেকোনো ম্যানেজার/এডমিন) এখন তালিকা থেকে **নির্দিষ্ট একটি পণ্য সরাসরি মুছে ফেলতে** পারেন (✕ বাটন) — পুরো তালিকা না মুছেও।
- যাকে তালিকা পাঠানো হয়েছে, সে কোনো পণ্য কিনতে না পারলে কারণ জানাতে পারে — **❌ পাওয়া যায়নি**, **💸 দাম বেশি**, অথবা নিজের মতো **📝 নোট** লিখে। এই কারণটা তালিকায় সবসময় দেখা যায় (পাঠানো ব্যক্তিসহ), যতক্ষণ না কেউ সেটা মুছে দেয় (✕) বা পণ্যটা কেনা/মুছে ফেলা হয়।
- একটি তালিকা শুধু তৈরিকারী, যাকে অ্যাসাইন করা হয়েছে, ও মালিক/এডমিন দেখতে পারেন — Firestore rules-এ প্রয়োগ করা, ফ্রন্টএন্ডে লুকানো নয়।
- **যাকে অ্যাসাইন করা হয়েছে সে-ও নতুন পণ্য যোগ করতে পারবে** — তালিকার ভেতরে "+ নতুন পণ্য যোগ করুন" দিয়ে, শুধু তৈরিকারী নয়।
- **কার জন্য সবচেয়ে বেশি তালিকা বানিয়েছেন**, সেই মানুষটি "কার জন্য" ড্রপডাউনে সবার উপরে থাকে ও নামের পাশে ⭐ চিহ্ন দেখায়।
- তালিকা কে পাঠিয়েছে তা তালিকার ভেতরে দেখা যায়, এবং তার মোবাইল নাম্বার দেওয়া থাকলে সরাসরি 📞 কল ও 💬 WhatsApp বাটন থাকে (`tel:`/`wa.me` লিংক)।
- পরিমাণ/দাম দিয়ে টিক দেওয়া ও "সংরক্ষণ করুন" — সবকিছু একই স্ক্রিনে হয় বলে কেনার পর আলাদা কোনো পেজে যাওয়া লাগে না; বাকি পণ্যগুলো তখনই একই জায়গায় দেখা যায়।

### লাইভ সিঙ্ক (Realtime)

সদস্যের তালিকা (নাম/ফোন/রোল/অনুমতি), বাজারের তালিকা, আর মাসিক খরচের সংখ্যাগুলো (`memberMonthly`/`memberCategoryMonthly`) এখন Firestore-এর `onSnapshot` দিয়ে **সরাসরি লাইভ** — কেউ নাম বদলালে, বা কারও জন্য তালিকা বানালে, বা কেউ নতুন বাজার যোগ করলে, অন্য সব সদস্যের স্ক্রিনে তা রিফ্রেশ/রিলোড ছাড়াই সাথে সাথে দেখা যায় (অ্যাপ খোলা থাকা অবস্থায়)। বাকিটা (বাজেট, ক্যাটাগরি, পণ্য তালিকা, দামের ইতিহাস) আগের মতোই — কেনাকাটা যোগ/সম্পাদনার পর একবার রিলোড হয়, কারণ এগুলো কম পরিবর্তনশীল আর প্রতিটির জন্য আলাদা listener রাখা অপ্রয়োজনীয় খরচ।

### "কে কত খরচ করেছে" = ফ্যামিলি বাজার + অন্যান্য খরচ

প্রতিটি সদস্যের সারিতে দেখায়: `৳৫০০ ফ্যামিলি বাজার + ৳৬,৫০০ অন্যান্য খরচ = ৳৭,০০০`।
- **ফ্যামিলি বাজার** = সে ফ্যামিলি বাজারে যা কিনেছে।
- **অন্যান্য খরচ** = তার নিজের ড্যাশবোর্ড টাইমলাইনের বাকি সব ব্যয় (ফ্যামিলি বাজার থেকে আসা লেনদেন বাদ, যাতে দুবার গোনা না হয়)। প্রতিটি সদস্যের অ্যাপ এই মোটটা নিজে থেকে পরিবারে প্রকাশ করে (`memberOtherMonthly`); দেখতে পান শুধু "মাসিক মোট" অনুমতি থাকা সদস্যরা। নিজের সারিতে সবসময় নিজের ফোনের সর্বশেষ সংখ্যা।
- উপরের "এই মাসে পরিবারে বাজার খরচ" শুধু ফ্যামিলি বাজারের খরচ — **যে সদস্য পরিবার ছেড়েছেন/বাদ পড়েছেন তার হিসাব এতে ধরা হয় না** (তার পুরনো কেনাকাটার রেকর্ড থেকে যায়)।

### Back বাটন

সব স্ক্রিন এখন একটা স্ট্যাক: তালিকা → তালিকার ভেতর → কেনার ফর্ম — প্রতিবার back করলে ঠিক এক ধাপ পেছনে যায়, ড্যাশবোর্ডে নয়। "আরও"-র ভেতরের পাতা (পণ্য তালিকা, ক্যাটাগরি, খুঁজুন, বাজেট) থেকেও ফোনের back আগে "আরও" মেনুতে ফেরায়।

### বাজারের তালিকা কেন আগে দেখা যেত না (আসল কারণ)

Firestore rules ফিল্টার নয়: rule বলে "যে তৈরি করেছে বা যাকে দেওয়া হয়েছে সে-ই পড়তে পারবে" — তাই পুরো কালেকশন একসাথে চাইলে মালিক/এডমিন ছাড়া বাকিদের পুরো কোয়েরিটাই প্রত্যাখ্যাত হয়। এখন দুটো শর্তযুক্ত কোয়েরি (`assignedTo == আমি`, `createdBy == আমি`) চলে, ফল একসাথে জোড়া হয়। `tests/firebase-queries.test.js` এটা পাহারা দেয়।

### পণ্যের ক্যাটাগরি ঠিক করা (বানান ভুলে ডুপ্লিকেট আইটেম হলে)

কোনো পণ্যের পাতায় (Product Sheet) গিয়ে, মালিক/এডমিন সেই পণ্যের ক্যাটাগরি বদলে দিতে পারেন — যেমন বানান ভুলে "চাল" আলাদা আইটেম হিসেবে অন্য ক্যাটাগরিতে ঢুকে গেলে, এখান থেকে ঠিক করা যায়। পুরনো কেনাকাটা/দামের ইতিহাস অক্ষত থাকে (`productId` একই থাকে, শুধু ক্যাটাগরি ট্যাগ বদলায়)।

### সদস্যের মোবাইল নাম্বার + মালিকের এডিট ক্ষমতা

- প্রতিটি সদস্য নিজের প্রোফাইলে ঐচ্ছিক মোবাইল নাম্বার যোগ করতে পারেন (নাম সংরক্ষণের পাশেই)। Invite পাঠানোর সময়ও নাম্বার দেওয়া যায় — সদস্য যোগ দিলে সেটা তার প্রোফাইলে বসে যায়।
- প্রোফাইল সম্পাদনায় আর "সম্পর্ক" নেই; সম্পর্ক শুধু "সম্পর্ক ও ভূমিকা" অংশে বদলানো যায়।
- **পরিবারের মালিক** যেকোনো (অন্য) সদস্যের নাম, ফোন নাম্বার ও সম্পর্ক বদলে দিতে পারেন — যেমন কেউ ভুল বানানে নাম লিখলে, বা কারও হয়ে ফোন নাম্বার যোগ করে দিতে চাইলে। এডমিন/ম্যানেজার রোল-পারমিশন বদলাতে পারে যথারীতি, কিন্তু প্রোফাইল তথ্য (নাম/ফোন) বদলানোর ক্ষমতা শুধু মালিকের।

## 📋 টাস্ক (Header-এর ছোট ক্যালেন্ডার আইকনের পাশে)

বিস্তারিত টাস্ক ফর্মে আছে: নাম, তারিখ, সময়, সাব-ক্যাটাগরি, নোট, রিমাইন্ডার প্রিসেট ও রিপিট। (আগের ঐচ্ছিক **পরিমাণ/টাকা** ফিল্ডটি সরিয়ে ফেলা হয়েছে — ফর্মে, টাস্ক লিস্টে এবং সংরক্ষণেও আর নেই। পুরনো টাস্কে আগে থেকে জমা থাকা `amount` মান নিরীহভাবে উপেক্ষা করা হয়, কোনো ডেটা নষ্ট হয় না।)

**টাস্ক যোগ করার ৩টি জায়গাতেই এখন হুবহু একই সাব-ক্যাটাগরি তালিকা** (Admin Task Management-এ যা আছে, ঠিক তা-ই): Header-এর কুইক-অ্যাড বার (এখন ছোট ক্যাটাগরি ড্রপডাউনসহ), "বিস্তারিত টাস্ক" ফর্ম, আর অ্যাডমিন Task Management ফর্ম — তিনটেই `useCategories().expenseCats` থেকে একই লিস্ট পড়ে, তাই অ্যাডমিন একটা ক্যাটাগরি যোগ/নাম বদলালে তিন জায়গাতেই সাথে সাথে বদলে যায়।

## 📋 খসড়া খাতা (☰ মেনু)

বাজার ও সদাই তালিকা: অনুষ্ঠান/সংস্থার নাম ও তারিখ, ডায়নামিক টেবিল (নং, বিবরণ, পরিমাণ, একক, দর, ছাড়, মোট), স্বয়ংক্রিয় হিসাব, খসড়া সংরক্ষণ, ইতিহাস থেকে সার্চ/দেখা, প্রিন্ট ও পিডিএফ।

| ফাইল | কাজ |
| --- | --- |
| `khasra-khata.js` | পুরো ফিচার — লজিক (হিসাব, Enter-নেভিগেশন, সার্চ, স্টোরেজ, প্রিন্ট HTML, পিডিএফ রাইটার) + তিনটি স্ক্রিন। `window.KhasraKhata`; `app.js`-এর আগে লোড হয় |
| `khasra-khata.test.js` | লজিকের টেস্ট (২০টি) |
| `khasra-ui.test.js` | স্ক্রিন/কিবোর্ড ইন্টারঅ্যাকশনের রেন্ডার টেস্ট (২০টি) |

- **লাইন মোট** = (পরিমাণ × দর) − ছাড়। ছাড় টাকায় (`৫০`) বা শতাংশে (`১০%`) লেখা যায়; ছাড় লাইনের মোটের চেয়ে বেশি হলে লাইন `০` থাকে (ঋণাত্মক হয় না)। বাংলা/ইংরেজি দুই ধরনের অঙ্কই চলে।
- **Enter নিয়ম:** বিবরণে Enter → নিচের লাইনের বিবরণ; শেষ লাইনে লিখে Enter → নতুন লাইন তৈরি (১০, ১১, ১২… যত ইচ্ছা); শেষ লাইনের বিবরণ ফাঁকা থাকলে নতুন লাইন হয় না। পরিমাণ/দর/ছাড়ে Enter → একই কলামের নিচের লাইন, শুধু যতগুলো লাইন তৈরি আছে ততদূর।
- সর্বমোট ছাড় ও সর্বমোট টাকা স্ক্রিনের নিচে সবসময় স্থির (sticky) থাকে।
- **ডেটা কোথায়:** শুধু এই ডিভাইসের `localStorage`-এ (`hisabkhata-khasra-v1:<uid|guest>`), লগইন করা অ্যাকাউন্ট অনুযায়ী আলাদা। ক্লাউড ব্যাকআপ/সিঙ্কে এটা যায় না — তাই আগের কোনো ডেটা-ফ্লো বদলায়নি।
- **প্রিন্ট:** লুকানো iframe থেকে `window.print()`। **পিডিএফ:** ব্রাউজারের ক্যানভাসে (বাংলা যুক্তাক্ষর ঠিক রেখে) A4 পৃষ্ঠা এঁকে নিজস্ব ছোট PDF-রাইটার দিয়ে ফাইল বানানো হয় — কোনো বাইরের লাইব্রেরি/নেটওয়ার্ক লাগে না।
- ⚠️ APK-তে (Capacitor WebView) `window.print()` ও ব্লব-ডাউনলোড সরাসরি কাজ নাও করতে পারে — APK ধাপে Capacitor `Filesystem` + `Share` প্লাগইন দিয়ে ফাইল সেভ/শেয়ার যুক্ত করতে হবে।

## 🌙 হিজরি ক্যালেন্ডার — উম্মুল কুরা (Umm al-Qura), ঢাকার সূর্যাস্ত অনুযায়ী

### বিশেষ দিবস — Bulk Import (অ্যাডমিন প্যানেল)

আগের "Date | Title | Description লিখে পেস্ট করুন" পদ্ধতির বদলে এখন খসড়া হিসাব খাতার মতো **সারি-ভিত্তিক টেবিল**: ১০টা লাইন দিয়ে শুরু হয়, বিবরণ/শিরোনাম ঘরে লিখে Enter চাপলে স্বয়ংক্রিয়ভাবে নতুন লাইন যোগ হয় (ঘর খালি রেখে Enter দিলে হয় না)। উপরে একটা টগল দিয়ে পুরো টেবিলের তারিখ **ইংরেজি** বা **হিজরি** ঠিক করা যায় — হিজরি মোডে প্রতিটা লাইনে শুধু দিন+মাস দিতে হয় (বছর লাগে না), আর প্রতিটা এন্ট্রি স্বয়ংক্রিয়ভাবে **"প্রতি হিজরি বছর" recurring** হিসেবে সংরক্ষিত হয় (Umm al-Qura ইঞ্জিন দিয়েই, যেটা আগে থেকেই আছে)। তারিখ ছাড়া কোনো লাইন সংরক্ষণ করতে গেলে লাইন নম্বর উল্লেখ করে স্পষ্ট এরর দেখায়। টেস্ট: `special-day-bulk-import.test.js`।

**জেনে রাখুন:** রমজান/শাওয়াল/জিলহজের প্রকৃত শুরু সরকারি চাঁদ দেখার ঘোষণার ওপর নির্ভর করে, তাই এই পূর্ব-গণনাকৃত তারিখ থেকে ±১ দিন আলাদা হতে পারে — এটা Umm al-Qura ক্যালেন্ডারের স্বাভাবিক সীমাবদ্ধতা, বাগ নয়।
